# 06 — Движок

## Стек

| Часть | Чем делаем |
|---|---|
| Сборка | Vite + React + TypeScript |
| Сцена | three.js, рендер в цель 480×270, вывод на экран с `NearestFilter` |
| Спрайты | плоскости с атласом, всегда лицом к камере |
| Таймлайн | свой, на одном `requestAnimationFrame`; время берётся от аудио |
| Звук | Web Audio API: воспроизведение файла, уровень и удары через `AnalyserNode` |
| Хранение | IndexedDB (дни пользователя) + статика в сборке (демо-дни) |
| Сервер | одна серверная функция на Vercel для вызова LLM |
| Экспорт | `canvas.captureStream()` + `MediaRecorder` → webm; ZIP папки дня |

Постоянного сервера и базы нет: данные не пропадут при перезапуске хостинга, дни жюри остаются в его браузере.

## Хореограф: сценарий → таймлайн

Вход: `script.json` и длительность фрагмента песни. Выход: список событий с точным временем.

1. Общая длина фильма: 30–60 секунд, по числу битов (`8 + 6 × биты + 8`).
2. Каждый бит — шаблон из шагов: подойти к слову → действие → превращение → реакция → камера.
3. Длительности шагов умножаются на коэффициент настроения (спокойно ×1,3, напряжённо ×0,7).
4. Начало каждого бита притягивается к ближайшему удару песни, если удары найдены.
5. Правила монтажа: первый бит всегда с общего плана; два `push_in` подряд не ставятся; противоречие получает `hold` 2–3 секунды; последний кадр — `pull_out`.
6. Фиксированный `seed` дня: случайные мелочи (наклон полароида, траектория листьев) одинаковы при каждом просмотре.

## Слово на странице

Текст дня выводится на плоскость страницы через canvas-текстуру. При вёрстке запоминаются прямоугольники каждого слова. Когда человечек «тянет» слово:

1. слово на текстуре страницы гаснет;
2. на его месте появляется отдельный спрайт с теми же буквами;
3. спрайт поднимается, проходит эффект «рассыпается в пиксели»;
4. на его месте появляется предмет, pop-up или эффект.

## Музыка

| Источник | Что получаем | Как |
|---|---|---|
| Аудиофайл | темп, уровень в реальном времени, удары | анализ в браузере |
| Ссылка | название и исполнитель | из страницы ссылки; темп и энергию оценивает LLM, человек поправляет ручками |

По ссылке трек внутри сайта не играет и не скачивается: есть кнопка «Открыть песню». Фильм в этом случае идёт под темп из сценария.

Можно ли получить 30-секундный фрагмент для анализа через открытые музыкальные API — не проверено; проверяем отдельно и только если останется время.

## Фото

- Уменьшение до 1024 px для хранения и до 768 px для LLM.
- Палитра: 5 основных цветов каждого фото, приведённых к мастер-палитре. Она сдвигает палитру дня.
- Полароид: фото в пиксельном виде на странице; по клику открывается оригинал.
- В pop-up-сцене фото становится задником диорамы.

Глубина и вырезание объектов моделями в браузере — не в этот дедлайн.

## Слои готовности

Каждый слой — рабочий продукт. Следующий не начинается, пока предыдущий не работает целиком.

| Слой | Что работает | Срок |
|---|---|---|
| 0 | Книга открывается, страница переворачивается, текст на странице, играет музыка, пиксельный рендер | ночь 20-го |
| 1 | Человечек ходит по странице, тянет слово, слово становится предметом; сценарий из JSON-файла | утро 21-го |
| 2 | Сценарий от LLM, ввод текста, фото и песни на странице, название на обложке | вечер 21-го |
| 3 | Полка-архив, сохранение, повторный просмотр, «Почему так» | ночь 21-го |
| 4 | Pop-up, противоречие, настроение меняет палитру и темп | утро 22-го |
| 5 | Экспорт видео и ZIP, второй человечек, реакция на удары песни | до 18:00 22-го |

Слои 0–3 закрывают все обязательные требования кейса. Слои 4–5 дают баллы за атмосферу.

## Производительность

- Цель: 60 кадров в секунду на среднем ноутбуке, 30 на телефоне.
- Низкое внутреннее разрешение делает сцену дешёвой; основной риск — число отдельных спрайтов. Частицы рисуются одним буфером.
- На телефоне камера стоит ближе к книге, полка открывается отдельным видом.
