# 05 — Режиссёр (LLM)

LLM не рисует. Она читает день и пишет сценарий фильма из готовых кубиков. Рисует код.

## Три слоя

1. **Режиссёр (LLM).** Вход: текст, уменьшенные фото, название и исполнитель песни. Выход: строгий JSON сценария.
2. **Хореограф (код).** Превращает сценарий в таймлайн с точными секундами. См. [06-engine](06-engine.md).
3. **Рендер.** three.js и пиксельный проход.

## Вызов

- Один запрос на день. Все фото и текст вместе: так модель видит противоречия между источниками.
- Фото уменьшаются до 768 px по длинной стороне перед отправкой.
- Ответ — структурированный вывод по JSON-схеме, без свободного текста.
- Модель задаётся переменной окружения `DIRECTOR_MODEL`. Начинаем с `claude-haiku-5-5`; если названия и объяснения выходят слабыми — `claude-sonnet-5-5`.
- Ключ только в серверной функции. Лимит запросов по IP, лимит расходов на ключе.
- Системный промпт (правила, каталог, образцовые истории) одинаковый для всех запросов и кешируется.
- Результат сохраняется в `script.json` и больше не пересчитывается.

Параметры вызова и названия полей API сверяем с документацией перед написанием серверной функции, по памяти не пишем.

## Схема сценария

```json
{
  "title": "Осенний парк и какао",
  "mood": { "warmth": 0.6, "tension": -0.4, "energy": -0.2, "openness": 0.3 },
  "contradiction": { "a": "холодно", "b": "уютно", "staging": "frost_edges_warm_center" },
  "time_of_day": "evening",
  "weather": "clear",
  "place": "park",
  "palette_hint": ["amber", "ochre", "slate_blue"],
  "song": { "tempo": "slow", "energy": 0.3, "estimated": true },
  "beats": [
    {
      "quote": "по парку",
      "action": "pull",
      "result": { "kind": "popup", "id": "tree" },
      "camera": "push_in",
      "effect": null
    },
    {
      "quote": "жёлтых листьях",
      "action": "shake",
      "result": { "kind": "effect", "id": "leaves" },
      "camera": "wide",
      "effect": "palette_shift"
    }
  ],
  "why": [
    "Текст: холод и тепло вместе → иней по краям и тёплый свет в центре",
    "Фото: много жёлтого → янтарная палитра",
    "Песня: медленный темп → спокойный шаг"
  ]
}
```

Правила схемы:

- `title` — 3–7 слов, на языке записи.
- `beats` — от 4 до 7.
- `quote` — точная подстрока текста пользователя. Код проверяет это и находит её координаты на странице.
- `action`, `result.id`, `camera`, `effect`, `staging`, `place` — только значения из каталога.
- `contradiction` может быть `null`.
- `why` — ровно три строки, по одной на источник.
- `song.estimated` — `true`, если темп оценён по названию, а не измерен по файлу.

## Каталог (закрытый список)

**Действия человечка:** `walk`, `pull`, `shake`, `carry`, `drink`, `sit`, `shiver`, `cheer`.

**Результат `popup`:** `tree`, `bench`, `lamp_post`, `house`, `work_desk`, `cafe_table`.

**Результат `item`:** 32 предмета из наборов 1 и 2 в [04-asset-list](04-asset-list.md).

**Результат `effect`:** `leaves`, `snow`, `rain`, `steam`, `frost`, `sparkles`.

**Результат `person`:** `second_person`.

**Камера:** `wide`, `push_in`, `pull_out`, `orbit_quarter`, `hard_cut`, `hold`.

**Эффект сцены:** `palette_shift`, `lamp_flicker`, `day_to_night`, `page_shake`.

**Постановка противоречия:** `frost_edges_warm_center`, `crowd_edges_alone_center`, `slow_walk_bright_light`.

**Место:** `park`, `home`, `office`, `cafe`, `street`, `nature`.

Каталог в коде — один файл `catalog.json`. Из него же собирается текст каталога для системного промпта, поэтому расхождений между промптом и движком нет.

## Системный промпт: что в нём

1. Роль: режиссёр короткого фильма по чужому дню. Только сценарий по схеме.
2. Принципы:
   - брать конкретные слова человека, а не пересказывать;
   - выбирать слова, за которыми стоит вещь, место, погода, ощущение или человек;
   - если в дне два противоположных чувства — заполнить `contradiction`, не усреднять;
   - не придумывать событий, которых нет в тексте и на фото;
   - не ставить диагнозов и не оценивать человека.
3. Каталог с короткими описаниями каждого id.
4. 6–8 образцовых пар «запись → сценарий», разных по настроению. Берём из [09-demo-days](09-demo-days.md).

## Страховка в коде

| Что пришло | Что делает код |
|---|---|
| `quote` нет в тексте | ищет ближайшее совпадение по словам; не нашёл — бит пропускается |
| id нет в каталоге | заменяется ближайшим по таблице синонимов; не нашёл — «кристалл памяти» из букв слова |
| Битов меньше 4 | добавляет биты `walk` + `sit` на самых длинных словах |
| Запрос отклонён или сеть упала | словарь-запасной вариант: ключевые слова → предметы, настроение по фото |
| Ответ дольше 20 секунд | показывается запасной сценарий, результат LLM подменяет его, если придёт до старта фильма |

Фильм собирается всегда.

## Оценка

Набор из 12 эталонных записей в `eval/stories.json`. Скрипт прогоняет все и считает:

1. JSON валиден по схеме.
2. Все `quote` — точные подстроки.
3. Все id из каталога.
4. Битов от 4 до 7, действия не повторяются больше двух раз подряд.
5. Для записей с заложенным противоречием поле `contradiction` заполнено.
6. Время ответа.

Плюс ручная оценка 1–5 по трём вопросам: похоже ли на день, хорошее ли название, понятны ли три причины.

Прогон на Haiku, Sonnet и Opus по одному разу — стоит центы. Решение о модели принимаем по таблице результатов, не на глаз.
